### Questions

- What is the overall page layout?
- What are the major regions of the page?
- Which elements should use Flexbox?
- Which elements should use CSS Grid?
- How should the statistics cards behave responsively?
- How should the task table behave at **700px width**?
- How should the task list behave at **400px width**?
- Should the table remain a table on mobile, or should the UI change?
- Which elements should be reusable React components?
- How would you structure the component hierarchy?
- How would you make the task list data-driven instead of hardcoding each row?
- What TypeScript types would you create for a task?
- What state does the page need?
- How would you add a new task?
- How would you mark a task as completed?
- How would you delete a task?
- How would you handle different task statuses?
- How would you handle different priorities?
- How would you handle long task names?
- What happens when there are no tasks?
- How would you make the dashboard accessible?
- What CSS decisions did you make, and why?
- Can you rebuild the layout from memory after deleting your CSS?

## Rules

- Don't use AI to build it.
- Don't use a UI component library.
- Don't copy a complete solution from the internet.
- You can use documentation when you forget syntax.
- Think before you code.
- Build the UI yourself.
- Keep the implementation simple.

> **You're doing this to challenge yourself, not to find the fastest way to finish it.**
